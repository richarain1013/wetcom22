# Windows 安全模式（本地用户隔离）

每个账号槽位对应一个 Windows **本地用户**（默认 `WeComSlot1`…`WeComSlot10`），用该用户身份启动官方 `WXWork.exe`，使企微配置/缓存落在独立用户配置目录下。

这是**合规隔离**增强，不是伪造设备指纹。服务端仍可能通过硬件特征关联同机账号。

## 使用步骤

1. **以管理员身份**打开 WeCom Launcher  
2. 勾选 **Windows 安全模式（本地用户隔离）**  
3. 设置用户前缀（默认 `WeComSlot`）和密码（≥8 位，需符合本机密码策略）  
4. 批量数量设为需要的账号数（如 8）  
5. 点 **准备本地用户**（会执行 `net user … /add`）  
6. 槽位表「本地用户」列变为绿色「已创建」后，再点 **分批启动**  
7. 各窗口分别扫码登录  

## 原理

| 步骤 | 行为 |
|------|------|
| 准备用户 | `net user WeComSlotN <密码> /add` |
| 启动 | `CreateProcessWithLogonW` + `LOGON_WITH_PROFILE` |
| 数据 | 各用户自己的 `%USERPROFILE%` / AppData |

## 注意

- 创建用户与部分启动场景需要 **管理员权限**  
- 密码仅用于本次启动调用，不要提交到 Git  
- 首次登录某用户时 Windows 可能初始化配置文件，稍慢属正常  
- 若启动失败，检查：密码是否正确、用户是否存在、域策略是否禁止批处理登录  
- 删除测试用户：`net user WeComSlot1 /delete`（管理员 CMD）  

## 与普通多开的区别

| | 普通多开 | 安全模式 |
|--|----------|----------|
| 进程用户 | 当前登录用户 | 独立本地用户 |
| 配置隔离 | 弱 | 较强（分 Profile） |
| 同设备指纹 | 相同 | 仍可能相同（硬件层） |
